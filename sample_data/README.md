# MukhaSpectra sample data

> **Research prototype — not for clinical use.** MukhaSpectra is a screening and triage aid. It is
> not a diagnosis: final diagnosis requires a clinician and histopathology.

This folder holds two things:

| Folder | What it is |
|---|---|
| [`synthetic/`](synthetic/) | Three **SYNTHETIC** demo patients (`low`, `moderate`, `high`), generated by `mukha_pipeline.synthetic`. |
| [`bench/`](bench/) | Empty slots and conventions for real TRL-3 bench data (phantoms, ex vivo tissue, consented team volunteers). See [`bench/README.md`](bench/README.md). |

## SYNTHETIC demo patients

Every file in `synthetic/` was generated by software. **No real person, patient or tissue is
behind any of it.** It exists so the full flow (upload → QC → registration → autofluorescence
analysis → probe spectra → triage → PDF report) can be demonstrated and tested without hardware
or patient data.

### How everything is labelled SYNTHETIC

* **Pixels:** every white-light (WL) image has a dark "SYNTHETIC" label in the bottom-left
  corner. Autofluorescence (AF) images carry the same text at the same pixels (a camera-fixed
  label, which the registration step recognises and ignores). Dark frames carry no pixel label,
  because dark subtraction would copy it into the AF image; they are labelled by file name and
  metadata.
* **File names:** `SYNTHETIC_<site>_wl.jpg`, `SYNTHETIC_<site>_af.jpg`, `SYNTHETIC_<site>_dark.png`.
* **File metadata:** the JPEG/PNG EXIF says "SYNTHETIC image generated by mukha_pipeline.synthetic
  - not a real patient", camera make "MukhaSpectra SYNTHETIC", device `SYN-SCOUT-01`.
* **Manifests:** `"data_provenance": "synthetic"`, patient names `SYNTHETIC PATIENT LOW` etc.,
  pseudonymous ids `SYN-...`, camp `SYNTHETIC DEMO CAMP`, health worker `SYN-HW-01`.
* **Results and reports:** the pipeline marks the screening synthetic, so results carry the
  synthetic notice and the PDF report carries a "SYNTHETIC DATA" watermark on every page.

### Contents of each patient folder

| File | Content |
|---|---|
| `SYNTHETIC_<site>_wl.jpg` | White-light close-up, 1024 × 768, JPEG quality 92 |
| `SYNTHETIC_<site>_af.jpg` | 405 nm autofluorescence capture of the same site, slightly misaligned on purpose (rotation ≤ 1.5°, shift ≤ 12 px, scale ≤ 2 %) to exercise registration. sRGB-encoded like a phone JPEG; the fluorescence (and its loss) is modelled in linear light |
| `SYNTHETIC_<site>_dark.png` | Dark frame (LEDs off, AF exposure), in the same encoded file values |
| `spectrum.csv` | Confirm-probe AS7341 raw counts in the spectral CSV v1 format (`docs/pipeline_contracts.md`), with `white` / `white_dark` rows when the case is calibrated |
| `manifest.json` | Upload manifest (`docs/architecture.md` §6). Each `wl`/`af`/`dark`/`spectral_file` value is the file name without its extension, i.e. the multipart field name to use |

### The three cases

The "designed to exercise" column says which triage rule path each case was built for under
`triage_rules.v1.yaml`. It is design intent for a software demo, **not** a measured result.

| Case | Sketch | Sites | Probe | Designed to exercise |
|---|---|---|---|---|
| `low` | 34-year-old woman, no tobacco, areca nut or alcohol | buccal mucosa L/R, lateral tongue L/R; healthy; one small plaque (porphyrin) spot at a gingival margin | normal reference pair, calibrated | LOW: routine re-screening and counselling ("this does not rule out disease") |
| `moderate` | 46-year-old man, khaini for 12 years, sharp molar cusp | homogeneous white patch on the left buccal mucosa with only mild, sub-threshold fluorescence dimming; right buccal mucosa as reference; lateral tongue L/R | patch vs right cheek, **no** white reference (relative-signal path) | MODERATE via the health worker's white-patch observation: remove irritants, re-examine in 2 weeks |
| `high` | 58-year-old man, gutka 20 years, bidi 15 years, daily alcohol, sore for more than 2 weeks | red patch with white specks and an irregular border on the right lateral tongue with marked fluorescence loss; left lateral tongue as reference; buccal mucosa L/R | lesion vs left tongue, calibrated against a white standard | HIGH: urgent referral for specialist examination and biopsy |

### Never use these files for performance claims

These images and spectra come from a hand-written forward model with parameters chosen to look
plausible. They contain no information about how any patient's tissue looks or behaves. Do not
train, tune, validate or evaluate any model on them for a claim, and never quote a number
(accuracy, sensitivity, specificity, agreement, or anything else) computed on them. They are
for demos, software tests and report layout only.

### What the generator models, and what it does not

Modelled, simply: moist pink-red mucosa with colour variation, fine vessels and wet highlights;
site anatomy (tongue papillae and coating, stippled gingiva, linea alba, palatal rugae, labial
glands, ventral veins); teeth with embrasures and tobacco staining; the dark oral cavity and
torch fall-off; white patch, red patch, mixed red-white and ulcer appearances; green
autofluorescence with loss over the lesion mask (red/green ratio rising there), bright teeth,
red porphyrin spots, bloom, sensor noise and a dark pedestal, all in linear light and then
sRGB-encoded as a phone stores a photo (the fluorescence-loss depth is a fraction of light, which
the analysis recovers only by linearising first, as it must for real uploads); AS7341 counts from
a white-LED, filter-response and haemoglobin-absorption model.

Not modelled: oral submucous fibrosis (blanching, fibrous bands), melanin pigmentation,
keratin-bright autofluorescence of thick plaques, inflammation that mimics fluorescence loss,
saliva bubbles, motion blur, out-of-focus captures, real camera colour pipelines and tone curves
(beyond the plain sRGB encoding), a strongly uneven violet-LED profile (the demo calibration's
flat fields are neutral), and the variety of real patients. Real bench and field data are needed for all of that.

### Regenerate

From the repository root:

```bash
.venv/bin/python -m mukha_pipeline.synthetic                    # writes sample_data/synthetic/
.venv/bin/python -m mukha_pipeline.synthetic /tmp/demo --seed 3  # another folder, another seed
.venv/bin/python -m mukha_pipeline.synthetic /tmp/small --size 384x512
```

Output is deterministic for a seed: regenerating with the same code and seed rewrites the same
bytes. In Python, `mukha_pipeline.synthetic.make_demo_patient("high")` returns the same patient as
a `ScreeningInput`, without touching the disk.
