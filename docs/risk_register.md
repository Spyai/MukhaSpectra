# Risk register (ISO 14971 style)

> Research prototype — not for clinical use. This register is written now, while the software is
> small, because MukhaSpectra may become Software as a Medical Device. Each hazard lists the
> sequence of events, the harm, the controls built into the software, and how each control is
> verified. Severity (S) and probability (P) are qualitative, before controls: 1 (low) – 5 (high).

| ID | Hazard → sequence of events | Harm | S | P | Risk controls in software | Verification |
|---|---|---|---|---|---|---|
| H1 | **False reassurance.** A lesion that needs biopsy is shown as LOW. Causes: dysplasia without FVL (thick keratin can stay bright), poor images, lesion outside captured sites, white patch dropped by segmentation as "teeth", diseased reference site making relative AF look normal, thresholds tuned on synthetic data. | Delayed referral, later-stage disease | 5 | 3 | Clinical red-flag **floors** the device can never lower (non-healing ulcer > 2 weeks, red patch, growth, neck lump → HIGH; white patch, ulcer, trismus, bleeding → MODERATE). LOW requires every examined site to be analysed, otherwise INCONCLUSIVE. LOW wording: "does not rule out disease", routine re-screening. Segmentation fills holes enclosed by mucosa so white patches stay in the analysis. FVL on a reference site is still scored and flagged as a limitation. Every result is "Pending clinician review". Thresholds are labelled baseline/unvalidated. | Fusion tests (floors, INCONCLUSIVE rule, habits never raise LOW), segmentation hole-fill test, reference-site FVL test, positioning tests |
| H2 | **False alarm / over-referral.** FVL caused by inflammation, plaque porphyrins, pigmentation, blood, glare or normal keratinised tissue. | Anxiety, wasted referral capacity, loss of trust in screening | 3 | 4 | Confounder detection (red porphyrin, pigmentation, blood, glare) discounts AF points and is shown per region. Diascopy result (FVL resolves under pressure) discounts AF. Lower AF weight at gingiva, tongue dorsum, hard palate. MODERATE path is "remove irritants, re-examine in 2 weeks" before referral. Clinician review. | AF confounder tests, fusion discount tests |
| H3 | **Output read as a diagnosis.** Wording implies the device diagnoses. | Patient skips biopsy, or undue alarm | 4 | 3 | Positioning guard bans diagnosis / malignant / cancer detected / no cancer outside mandated disclaimers, across UI strings, report HTML/PDF, API output and configs. Banner "Research prototype — not for clinical use" on every screen and report page. Disclaimer box on every report. | `test_positioning`, report and frontend positioning scans |
| H4 | **Reliance on an unvalidated model.** A placeholder or untrained model drives the risk level. | Wrong triage | 4 | 3 | WL classifier ships `model_unavailable`; when unavailable it contributes nothing. All models carry `validated: false`. Spectral classifier labelled placeholder. No accuracy numbers anywhere. Model status shown in report and UI. | WL classifier tests, fusion "WL unavailable contributes nothing" test, schema test `validated` default |
| H5 | **Synthetic data mistaken for real**, or used to support a performance claim. | Misleading evidence, regulatory harm | 4 | 2 | SYNTHETIC stamped in image pixels, file names, metadata (`synthetic: true`, provenance), result notice, UI ribbon and report watermark on every page. `ml/` rules forbid synthetic images in evaluation sets. | Synthetic watermark tests, report watermark test, UI ribbon test |
| H6 | **Left/right or site mix-up.** | Biopsy at wrong site, missed lesion | 4 | 2 | Site recorded in every capture's metadata. Site map drawn facing the patient with an explicit orientation note. Contralateral pairing defined in one catalogue. | Site catalogue tests, site map rendering tests |
| H7 | **WL↔AF misregistration.** Heatmap overlays the wrong tissue. | Wrong biopsy target | 3 | 3 | Registration confidence with sanity limits on translation/scale; low confidence fails QC and blocks analysis of that site; retake prompt. | Registration tests (recovery, failure → identity + not passed), QC registration tests |
| H8 | **Calibration drift** between devices or days. | Wrong absolute intensities | 3 | 3 | Daily calibration with expiry; missing or expired calibration marks results "uncalibrated" in the report. Decisions rely on within-patient relative AF (contralateral), which cancels device gain. | Calibration status tests |
| H9 | **Ambient light contamination** of AF or spectral readings. | Masked FVL, wrong spectra | 3 | 3 | Dark frame QC; warning when no dark frame. Spectral ambient-leak and contact checks. | QC dark frame and spectral QC tests |
| H10 | **PII exposure.** | Privacy harm (DPDP Act 2023) | 4 | 2 | PII in a separate table keyed by pseudonymous ID; results and the screening detail API carry no name. Consent required before anything is stored. (Phase 5: encryption at rest, RBAC, full audit.) | API tests: no PII in result JSON or detail endpoint; consent-missing stores nothing |
| H11 | **Silent overwrite of a result.** | Clinician acts on a changed report without knowing | 3 | 2 | Re-analysis writes a new result version with `supersedes_result_id`; reports are versioned and stored. | API reanalysis/version tests |
| H12 | **Report mixed up between patients.** | Wrong patient referred | 4 | 2 | Report ID, pseudonymous ID and QR link to the record on every report. | Report tests |
| H13 | **Delayed action on HIGH.** | Progression | 5 | 2 | HIGH action is "urgent referral" with a timeline in days and steps. (Phase 4: immediate notification of HIGH to the review queue.) | Fusion action tests |
| H14 | **Violet LED exposure** (Phase 3 hardware). | Eye or tissue discomfort | 3 | 2 | Firmware auto-off ≤ 10 s per exposure, hard duty-cycle cap. | Firmware tests (Phase 3) |
| H15 | **Spectral probe without contact** or saturated. | Wrong spectral features | 2 | 3 | Contact (CLEAR/NIR), saturation, repeatability and signal checks; failed QC skips the spectral classifier. | Spectral QC tests |
| H16 | **Untraceable result** (unknown thresholds or software version). | Cannot investigate an incident | 3 | 2 | Every result records software, pipeline, schema, model and config versions with SHA-256 of each config file; the report prints them. | Schema/version tests, report header test |

Residual risks accepted for the research prototype: thresholds are not clinically validated
(H1, H2); bilateral disease can mask relative FVL (H1, mitigated by clinical floors and review);
no learned model yet (H4). None of these is acceptable for clinical use; clinical validation with
biopsy-linked ground truth (Phase 4 flywheel) is required before any change in positioning.
